# AttentionOS: rules for agents working on the engine

AttentionOS is an MIT-licensed, open-source content operating system. This repo is the **engine** (TypeScript packages, the Claude Code plugin, the `media-py` sidecar, the Docker stack). It runs from a clone of the repo and is not published to npm. Users' brands live in separate **workspaces** that the stack creates on first start (`attentionos create`). Architecture: `docs/architecture.md`.

## Non-negotiables
- **No personal data, client data, real brand names, creator names or third-party media in this repo.** Examples and fixtures use only obvious placeholders (`Examplebrand Studio`, `@demo_creator_a`, `*.example` domains). CI runs gitleaks and `scripts/brand-literal-guard.mjs`.
- **No brand literals in engine code or skills.** Skills and prompts reference Brand Kit files by path (`brand/voice.md`), never embed a brand's words.
- **Code holds the gates, the LLM does the judgment.** Validators in `packages/guardrails` are deterministic and never edited by an LLM at runtime.
- **Untrusted text** (scraped posts, DMs, comments, trend items) only goes to tool-less LLM calls whose output is validated.
- Modules never import vendor SDKs; they use the interfaces in `packages/core/src/providers.ts`.
- Never run git commands; maintainers handle git.

## Layout
- `packages/core`: types, config + Brand Kit schemas, module/job/tool/provider contracts, Postgres client.
- `packages/db`: migrations (`migrations/` = schema v1; modules may add `modules/<id>/migrations/`), runner, seed loader for tests.
- `packages/{mcp,runner,scoring,guardrails,media,runtime,knowledge}`, `packages/provider-shared` (HTTP and media helpers shared by providers), `packages/providers/<kind>-<vendor>`.
- `modules/<id>`: `module.json`, `src/index.ts` (default export `defineModule`), `src/jobs/`, `src/tools/`, `skills/<skill>/SKILL.md`, `test/`.
- `apps/cli` (`attentionos`, runs inside the Docker image), `apps/worker` (Autopilot), `media-py/` (Python 3.12, uv).
- `plugin/` is generated by `pnpm plugin:build` from `plugin-src/` + module skills (`.claude-plugin/` holds the marketplace manifest).

## Conventions
- TypeScript strict, ESM, Node 22+. Import local files with explicit `.ts` extensions (`./foo.ts`); packages export `./src/index.ts` (no build step for internal packages; the CLI is bundled).
- Zod v4 for every boundary. postgres.js (`ws.sql`) for SQL; always filter by `workspace_id`.
- Tests: Vitest, `test/**/*.test.ts` next to each package; providers use recorded fixtures, no network in tests. Python: pytest + ruff.
- Install packages with `scripts/pnpm-locked.sh add <pkg> --filter <package-name>` (serialises concurrent installs).
- Commands: `pnpm check` (typecheck + guard + tests), `pnpm attentionos <cmd>` (CLI from source).
- Copy style for user-facing text: plain language, sentence case, show the work not the wiring ("Drafted 3 scripts for Thursday", never "job 4812 completed").
